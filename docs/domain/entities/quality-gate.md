# Сутність: Quality gate

## Призначення

Quality gate дає один детермінований вердикт «пройдено / не пройдено» для рішення, чи можна приймати зміну, і показує, що виправити. Перша версія лише не дозволяє погіршити стан відносно бази: абсолютні пороги на наявному коді були б червоними одразу. Команда `osavul gate <база> <ревізія>` порівнює два коміти локального Git; ревізії розв'язуються як у `complexity`, база не мусить бути предком. Форма `osavul gate <база> --path <тека>` перевіряє зміну до коміту: перелік файлів дає Git (відстежувані та невідстежувані неігноровані), байти беруться з диска, а шляхи в подробицях мають дослівний префікс аргументу теки. Для однакового вмісту обидві форми дають однакові суми, стани й код.

## Умови

Кожне зареєстроване правило `check` (зараз `empty-test`) і `duplication` — окрема умова. Умова порушена, коли проєктна сума в ревізії більша за суму в базі: число знахідок правила або `duplicatedLines` за методикою `ts-duplication` ([Знахідка](finding.md), [Звіт дублювання](duplication-report.md)). Пороги вшиті, налаштувань і придушення немає. Відбір файлів однаковий для обох боків; `target` виключено лише для правил.

## Як читати результат

Рядок стану кожної умови містить суми бази й ревізії; gate пройдено, лише коли жодну умову не порушено. Суми — єдине, що визначає стан. Місця під порушеною умовою лише пояснюють його: для правила це всі знахідки файлів, де їх побільшало, для дублювання — усі входження груп, що зачіпають файл зі зростанням, зокрема партнерів у незмінених файлах. Окремі знахідки між боками не зіставляються, тож виправлена й водночас додана знахідка того самого правила умову не порушує; зменшення за одним правилом не компенсує зростання за іншим. Перейменування без зміни вмісту вердикту не змінює.

## Наслідок неповної бази

Заниження базової суми через непридатний файл бази може дати зайве «не пройдено», але ніколи хибне «пройдено». Якщо вердикт «не пройдено» з'явився поряд із попередженням про базу, перегляньте, чи зростання не зумовлене файлом, якого база не змогла врахувати. Вердикт «пройдено» довіри не втрачає: справжня база не нижча за відому.

## Стани й інваріанти

- Код `0` — пройдено, `1` — не пройдено; в обох випадках stdout містить повний вердикт. Код `2` означає, що вердикт визначити неможливо (аргументи, Git, ревізія, помилка читання, декодування, розбору чи подання шляху будь-якого файла ревізії, недоступний потрібний `rustc`, відмова запису); stdout порожній, а stderr називає кожен проблемний файл. Код `2` важливіший за вже виявлене погіршення.
- Помилка файла **бази** вердикт не блокує: у stderr є попередження з позначкою бази, шляхом і причиною, а внесок файла в кожній умові рахується за тим, що вдалося визначити (знахідки — нуль, дублювання — за успішними файлами). Ті самі внески використовуються й для суми, і для місць у поясненні. `rustc` потрібен, коли на будь-якому боці відібрано `.rs`, навіть якщо файл бази не читається: відсутність інструмента дає `2`, а не попередження.
- Однаковий вхід дає байтово однаковий stdout.
- Вміст береться лише з комітів: індекс, робоче дерево й невідстежувані файли не впливають.
- Рішення про порівняння сум пояснює [ADR-0005](../../architecture/decisions/0005-quality-gate-ratchet.md).
