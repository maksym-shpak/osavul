# Сутність: Звіт складності

## Призначення

Звіт складності — результат вимірювання цикломатичної складності всіх звичайних файлів `.ts` одного Git-коміту або вказаного локального файла чи теки за методикою `ts-cyclomatic` версії 1. Людина чи агент бачить суму та внесок кожного файла й може звірити їх з іншим інструментом.

## Область

Три входи: коміт (`scope.input` = `git-tree`, `sha` — повний SHA), локальний файл (`file`) і локальна тека (`directory`); для локальних `sha` присутнє й дорівнює `null`.

**Локальний вхід** (`osavul complexity --path <файл-або-тека>`) читає поточний вміст диска й не потребує Git; відносний шлях відлічується від поточної теки процесу.

- Явний файл має точний, чутливий до регістру суфікс `.ts` за переданим іменем; єдиний запис містить це ім'я (для `src/branch.ts` — `branch.ts`). Явне кореневе символьне посилання розіменовується, суфікс і ім'я беруться з імені посилання.
- Тека обходиться рекурсивно; входять усі звичайні файли `.ts` (тести, `.d.ts`, невідстежувані й ігноровані Git). `.tsx` і `.TS` не входять. На кожній глибині пропускаються записи з іменами `.git` і `node_modules` та символьні посилання (на файли й теки); для кореня ці правила не діють.
- `path` — повний шлях відносно кореня теки з роздільником `/`; записи впорядковані за байтами всього шляху, а не за порядком файлової системи.

**Коміт:**

- Ревізію розв'язують один раз до повного SHA коміту; шляхи й вміст беруться з дерева цього коміту від кореня (індекс, робоче дерево й невідстежувані файли не впливають).
- Входять файли в режимі `100644` та `100755`, шлях яких закінчується точним суфіксом `.ts` (чутливим до регістру), зокрема тести й `.d.ts`. Символьні посилання та підмодулі пропускаються. Два шляхи до одного об'єкта дають два окремі записи.

## Методика `ts-cyclomatic`, версія 1

Аналіз синтаксичний: код не виконується, імпорти не завантажуються, типи не перевіряються. Вміст — UTF-8 (початковий BOM допустимий); для `.d.ts` діє режим декларацій.

- Початковий бал файла — `0`. Кожна функція з реалізацією (оголошення, функціональний вираз, стрілка, метод, конструктор, аксесор) додає `1`; вкладені рахуються кожна по одному разу. Сигнатури перевантажень, абстрактні методи й декларації без тіла дають `0`.
- По `1` додають `if` (також `else if`), умовний вираз `?:` часу виконання, `for`, `for…in`, `for…of` (також `for await…of`), `while`, `do…while`, кожна мітка `case` і `default`, кожен оператор `&&`, `||`, `??`.
- Власний внесок `switch`, `else`, `catch`, `finally`, `?.`, логічного присвоєння, параметра за замовчуванням і конструкцій рівня типів — `0` (умовний тип — `0`, тернарний вираз в ініціалізаторі параметра — `1`).
- Код поза функціями (модуль, виконуваний код `namespace`, ініціалізатори й статичні блоки класу) рахується за тими самими приростами без власного початкового бала.
- Перелік вичерпний; зміна правил потребує нової версії методики.

## Стани й інваріанти

- Верхні поля JSON ідуть у порядку `sha`, `source` (`osavul`), `methodology` (`id`, `version`), `scope` (`input`, `entries`, `suffix`), `complete`, `files`, `total`. Вивід — один компактний об'єкт UTF-8 із завершальним LF.
- `sha` — рядок лише для коміту, інакше явне `null`.
- `files` містить рівно один запис на відібраний шлях, упорядкований за байтами шляху. Успішний запис має `path` і ціле невід'ємне `cyclomatic`; `0` — дійсне число.
- Шлях поза UTF-8 записують як `path: null`, а наступне поле `pathBytes` містить усі його байти малими шістнадцятковими цифрами. Кодування імені не впливає на аналіз вмісту.
- Файл, що не читається, не декодується як UTF-8 або має синтаксичну діагностику (зокрема за відновленого дерева), зберігає шлях, має `cyclomatic: null` і `error` зі стабільною причиною: `read-error`, `invalid-utf8` або `syntax-error`. Решту файлів однаково опрацьовують.
- `complete` істинне, лише коли кожен шлях має число. Тоді `total` — сума всіх значень (для порожнього інвентарю `0`); інакше `complete` хибне, `total` — `null`.
- Межа між неповним звітом і фатальною помилкою: якщо відомо, що файл — звичайний `.ts`, відмова читання, UTF-8 чи розбору належить до його запису (код `1`). Якщо шлях відсутній, корінь недоступний чи непідтримуваного типу, суфікс явного файла не `.ts` або повний перелік скласти неможливо (помилка переліку теки чи визначення типу запису), JSON не виводиться: порожній stdout, діагностика в stderr, код `2`.
- За однакових доступних об'єктів, SHA та версії Осавула повторні запуски дають байтово однаковий JSON. Для локального входу умова — однакові шляхи, вміст, результати читання й версія; атомарного знімка диска під час запуску не гарантується.
