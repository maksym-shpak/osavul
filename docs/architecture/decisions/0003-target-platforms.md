# ADR-0003: Цільові платформи Осавула
Статус: `Accepted`

## Контекст

Осавул читає локальні файли, об’єкти Git і шляхи звітів LCOV, а їхнє подання залежить від ОС. Людина вирішила, що платформи підтримуються явно. Історичні мотиви вибору саме цих платформ невідомі.

## Рішення

Підтримуються рівно три цілі: Ubuntu Linux (`x86_64-unknown-linux-gnu`), Windows (`x86_64-pc-windows-msvc`) і macOS на Apple Silicon (`aarch64-apple-darwin`). Інші ОС і архітектури не є цільовими. Контракт звіту й коди завершення однакові на всіх цілях.

На Windows гарантовано точність локальних імен, які можна подати в UTF-8. Для імені з непарним сурогатом наявне перетворення може замінити його на U+FFFD, і різні імена дадуть однаковий ключ. Окремого формату для таких імен немає. Байти шляхів у дереві Git мають власний контракт (`path: null`, `pathBytes`) і від цієї межі не залежать.

## Альтернативи

Безвтратне кодування непарних сурогатів у публічному звіті відкинуто людиною: гарантія UTF-8 достатня й зберігає чинний формат ключів. Розглянуті альтернативні набори платформ невідомі.

## Наслідки

- Clippy з Linux для трьох цілей (разом із тестовими цілями Cargo) перевіряє компіляцію й лінти, але не поведінку.
- Канали stdout, передавання нативних аргументів, реальні шляхи ОС (зокрема LCOV), права доступу та робота Git підтверджуються лише запуском на відповідній ОС.
- Тести фізичних можливостей (невалідні байти в імені файла на Linux, POSIX-права й посилання, утримуваний дескриптор на Windows) обмежені цією можливістю; прогалини названо в [політиці тестування](../../testing-policy.md).
