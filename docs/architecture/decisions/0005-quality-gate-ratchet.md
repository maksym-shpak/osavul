# ADR-0005: Quality gate порівнює суми з базою
Статус: `Accepted`

## Контекст

Агентові й людині потрібен один вердикт, чи можна приймати зміну. Наявний код уже містить порожні тести й дублювання, тому абсолютні пороги були б червоними з першого запуску й їх довелося б ігнорувати. За [ADR-0001](0001-deterministic-static-analysis.md) вердикт має бути детермінованим, а за [ADR-0004](0004-check-engine-and-rules.md) нові правила мають потрапляти в перевірку без змін у gate.

## Рішення

Gate порівнює проєктні суми кожної умови між базою й ревізією: число знахідок кожного зареєстрованого правила та `duplicatedLines` за `ts-duplication`. Умова порушена, коли сума зросла. Порогів, налаштувань і придушення немає. Знахідки між боками не зіставляються; за порушення місця пояснюються лише за зростанням у файлах за тим самим кореневим шляхом.

## Альтернативи

Абсолютні пороги відхилено: вони блокують будь-яку зміну на наявному коді. Зіставлення окремих знахідок між боками відхилено для першої версії: воно потребує стабільної ідентичності знахідки, яку перейменування й зсув рядків роблять ненадійною.

## Наслідки

- Існуючий борг не блокує зміну; стан не можна погіршити.
- Ціна: виправлена знахідка компенсує додану того самого правила в іншому місці, тож заміна проблеми проблемою проходить.
- Якщо файл бази неможливо прочитати чи розібрати, його внесок вважається нижчим за фактичний, тож можливе зайве «не пройдено», але не хибне «пройдено».
- Нове правило з реєстру `check` стає умовою автоматично.
