## Порядок звірки

1. Перевірити, що збережений звіт відповідає SHA.
2. Для кожного SHA: `osavul complexity <sha> > osavul-<sha>.json`; очікується код 0 і `complete: true`.
3. Порівняти множину `files[].path` з усіма `.ts` у `analyzedPaths` — потрібна точна рівність (664 і 665 шляхів); кожному шляху має відповідати рівно одне числове `files[].cyclomatic` у звіті SonarQube.
4. Зіставити значення кожного файла за точним шляхом, навіть коли суми збігаються.
5. Записати суми Осавула для обох SHA, їхню різницю поруч із 83 130 → 83 630 (+500).
6. Для кожного відмінного файла: SHA, шлях, обидва бали, різниця «Осавул мінус SonarQube», конструкції й правила, що пояснюють усю різницю. Кожне правило розбіжності має бути задокументоване у [методиці](../domain/entities/complexity-report.md) і відтворене малим тестом у `src/ts_cyclomatic.rs`. Якщо всі значення збіглися — зафіксувати кількість перевірених шляхів для кожного SHA.

Звірку завершено лише за повного покриття шляхів і пояснення кожної відмінності.
